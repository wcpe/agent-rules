# PR 生命周期规则（适用于所有仓库）

## 禁止关闭 PR

- 任何仓库禁止主动 close PR：遗留/被取代的 PR，下一次改动直接复用覆盖它（同分支强推或改造），保留编号与讨论链
- 只有用户明确说关才关

## 合并授权

- 未获本次任务明确授权不得合并 PR
- 授权通常附条件：验收通过 + 本机测试全绿后再 squash
- 等待外部检查期间不要空停：先本机跑全部测试修掉问题，等待期间并行验收下一个 PR

## 审查纪律

- PR 默认三轮 code review + 三轮修复，解决全部问题并本机测试全绿后再交用户审批
- 审查者与评论机器人给的是反馈不是命令：实质性方向改动升级给用户裁定

## 关联 issue

- 关闭关键词写英文 `closes #n`/`fixes #n`/`resolves #n`（中文写法无效），写在 PR 描述里
- 合并到非默认分支时 GitHub 不自动关 issue，须手工关闭并注明合并提交 SHA、改动要点、验证方式

## 分支与叠加

- 堆叠 PR 要注意级联关闭风险：base 分支被合并删除时以其为 base 的 PR 会被 GitHub 自动关闭且禁止重开——栈层 base 优先挂主线分支
- 合并时谨慎使用 --delete-branch：若 head 分支还要复用（如回馈上游的 topic 分支）则保留
