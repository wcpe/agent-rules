# 实现纪律（适用于所有仓库）

## 复用优先（硬规则）

- 写代码前先查仓内已有构件：要新增的功能、工具函数、组件、配置通道，先检索仓库是否已有可复用实现（含平台/标准库原生能力），有则复用或扩展，不得另起炉灶平行造一份
- 引入新依赖或手写已有能力的等价物必须论证：在提交信息或 PR 描述里说明为什么现有构件/依赖不满足——「不知道已有」不是理由，检索动作本身是义务
- 最小实现偏向：只写任务需要的代码，但禁止以「少写」为由砍掉校验、错误处理、安全性、可访问性、文档同步义务——代码量小应该是「必要所以小」，不是裁剪出来的小
- 清理义务对称：复用取代旧实现时，旧路径的死代码一并删除或明确标注退役计划，不留双份平行实现长期共存
